# Convert C++ style comments

Support for C++ style comments in coding-standard configuration files is deprecated in
this release and support for JSON style comments is added. If you have added custom,
coding-standard configuration files to your Coverity Analysis installation and those
configuration files contain C++ style comments, you should either convert them to JSON
style comments or delete them.

Note: Because support for JSON style comments in coding-standard configuration files is
new in this release, you should first upgrade your Coverity Analysis installation and
then convert your C++ style comments to JSON style.

Use the following general format for your JSON style
comments:

```
"_comment_<whatever>": "<This is my comment text>",
```

For example, the following code shows two C++ style comments in an existing
coding-standard configuration file that shipped with previous releases:

```
// Do not edit this file! Make a copy and edit it to produce your own configuration
// Configuration for CERT, rule categories: L1, L2, L3
{
    "version": "2.0",
    "standard": "cert-c",
    "title": "CERT C All Rules",
    "deviations": []
}
```

The following code shows the same configuration file with the C++ style comments
converted to JSON style:

```
{
    "_comment_Warning": "Do not edit this file! Make a copy and edit it to produce your own configuration",
    "_comment_CERT_rule_categories": "L1, L2, L3",
    "version": "2.0",
    "standard": "cert-c",
    "title": "CERT C All Rules",
    "deviations": []
}
```

For more information about custom coding standards, refer to "Custom standards" in the Coverity Platform 2026.6.0 User and Administrator Guide.
For information about running a coding-standard analysis, refer to "Running coding-standard analyses" in the Coverity Analysis 2026.6.0 User and Administrator Guide.
