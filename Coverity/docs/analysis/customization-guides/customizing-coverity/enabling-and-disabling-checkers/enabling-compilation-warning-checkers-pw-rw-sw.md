# Enabling compilation warning checkers (PW.*, RW.*, SW.*)

When Coverity parses code for C/C++ source, it can detect various compilation issues.

The warnings generated by these checkers can number in the hundreds.
Because of this, the compilation warning checkers are disabled by default.

In general, compilation warnings are useful for identifying code quality issues,
while Coverity Analysis checkers are more effective at identifying
runtime issues.

You can use a configuration file to specify the warnings that are exposed as defects.
To create this file, refer to the sample parse warning configuration file, which shows all of the default settings.
This sample file is located in <install_dir>/config/parse_warnings.conf.sample.
You can also view its contents in this appendix.
Checkers are enabled or disabled by directives in this file. A parse-warning directive uses the following syntax:

```
chk "checker_name": on | off | macros | no_macros;
```

Here, "checker_name" is the name of the warning as shown in
Coverity Connect; for example,
PW.ASSIGN_WHERE_COMPARE_MEANT.

Individual parse warnings whose names start with RW or SW, unless they are explicitly disabled,
will be reported when parse warnings are enabled.
Parse warnings whose names start with PW will be reported only if they are explicitly enabled when
parse warnings are enabled.
To disable all parse warnings, you can add the `disable_all;` directive to the configuration file.
To disable individual warnings that are listed in the file, you can comment out their entries.

Parse warnings can be enabled by one of the following `cov-analyze` options:

- `--all`
- `--enable-parse-warnings`
- `--aggressiveness-level high`
