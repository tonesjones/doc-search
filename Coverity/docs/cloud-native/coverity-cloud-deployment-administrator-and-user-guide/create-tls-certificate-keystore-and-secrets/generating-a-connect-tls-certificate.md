# Generating a Connect TLS certificate

Coverity uses certificates to secure data in transit. Some certificates are used when
Coverity Connect is acting as a server; others are used when Coverity Connect is acting
as a client. Coverity Connect communicates over TLS/SSL to establish secure connections.
It uses Java keystores and truststores to communicate over TLS/SSL.

The easiest method is to use certificates generated by a common Certificate Authority for
all Connect instances.

To generate Connect certificates for a single standalone Coverity instance:

- To generate certificates using a Certificate Authority (CA), refer to the section,
  Generating a Coverity Connect TLS certificate signed by a Certificate Authority.
- If you are deploying within the AWS cloud and need to generate regional
  certificates, refer to the section, AWS: Downloading certificates and creating a truststore ConfigMap.
