# Connect-only quick start process - full version

This scenario provides a Coverity Connect-only quick start deployment for a single
instance of Coverity Connect and a PostgreSQL database within a Kubernetes cluster. The
following steps outline this deployment:

Important: These are Administrator procedures.

Table 1. Connect-only quick start

| Step | Description | Refer to |
| --- | --- | --- |
| 1 | Request access to Black Duck Community. | - Request access to Black Duck Community |
| 2 | Request a node-unlocked license for Coverity Connect from Black Duck Support. | - Obtain your Coverity licenses |
| 3 | Request Black Duck Docker registry credentials from Black Duck Support. | - Request Black Duck Docker registry credentials |
| 4 | Download the Helm chart from the Black Duck public Docker registry. | - Downloading the Helm chart from the Black Duck public Docker registry |
| 5 | Download any required open-source images. | - Open source container images |
| 6 | Highly recommended: Create a private Docker registry for downloaded Black Duck container images. | - Create your own private Docker registry |
| 7 | Manage container images. You can find this information within a single chapter.  You must either:   - Preferred method: Create and set up your own private image   registry. If you create a registry, you must pull, tag and push   images to your registry. - Alternate method: Set up the Helm chart to download images   directly from the Black Duck private registry during   deployment.   This chapter also describes the following relevant information:   - Introduces how Kubernetes manages container images  Lists of available container images and their purpose.  Note: You do not need to download Scan   Services images for a Connect-only deployment. - Describes how to create container image pull secrets. - How to configure the Helm chart for image access and   download. | - Managing container images |
| 8 | Download full Coverity Analysis client install files and other files as needed from the Black Duck private Docker registry:   - Download a full Coverity Analysis client file for the version   that will be used to perform local analyses. - Download platform files, host ID files, and documentation files   as needed. | - Downloading a full analysis client file from the Black Duck repository - Downloading platform, host ID, and documentation files from the Black Duck registry using curl |
| 9 | Infrastructure and configuration:   - Install required software. - Configure access privileges. - Create a Kubernetes cluster. - Expose the Kubernetes cluster. - Create a Kubernetes namespace. - Create or migrate a PostgreSQL database instance for each   instance of Coverity Connect. - Planning: Size the PostgreSQL pod resources. - Planning: Size Connect `cim` pod resources. - Configure Kubernetes logging.   You can set up the Kubernetes infrastructure either on-prem or in a provisioned cloud environment. If on-prem, you will need to obtain, install, and manage all components of the environment.  If you deploy Coverity Connect in the cloud, the cloud provider can provide and maintain Kubernetes as a provisioned service.  Platform-specific infrastructure and configuration:   - General/on-prem: - Amazon AWS - Google GCP - Microsoft Azure - Red Hat OpenShift   Note: This scenario assumes that you are not installing Scan Service in Kubernetes. Disregard all Scan Service, Storage Service, Cache Service, scan job, Redis, and MinIO requirements.  ARM64:   - If the cluster will use ARM64, create the ARM64 cluster, node   pools and tolerations. | Infrastructure and configuration:   - Install required software - Access privileges - Create a Kubernetes cluster - Expose the Kubernetes cluster - Create a Kubernetes namespace - PostgreSQL databases and PostgreSQL pod - Sizing PostgreSQL pod resources - Sizing a Coverity Connect (cim) pod for optimum performance - Configure Kubernetes logging   Platform-specific infrastructure and configuration:   - General/on-prem: Infrastructure and configuration - AWS only: Amazon AWS infrastructure and configuration - GCP only: Google GCP infrastructure and configuration - Azure only: Microsoft Azure infrastructure and configuration - Red Hat OpenShift, including OpenShift routing: Red Hat OpenShift infrastructure and configuration   ARM64:   - Setting up ARM64 support |
| 10 | Create the following secrets and configmap for Coverity Connect:   - Container image pull secret - Kubernetes ingress TLS secret - Connect license secret - Connect truststore - Create a secure Connect Web application administator   password. Important: When   you deploy Connect for the first time, we highly recommend   that you create a secure password for future administrator   access to the Connect Web application. If you do not create   a password, to re-connect to the web app as administrator,   you will need to manually create a password secret or   contact Black Duck Software for the default password.  Important: You must   also specify the name of the password secret in the   `cim.cimweb.adminPasswordSecret:` Helm   key. | Create TLS certificate, keystore, and secrets   - Create a container image pull secret - Create a Kubernetes ingress TLS secret - Create a Connect license secret - Creating a truststore ConfigMap for a Connect instance - Managing the Connect Web application administator password |
| 11 | Prepare a .yaml file containing the following Helm key overrides for the Coverity Connect deployment.   - Set the private image registry - Enable Connect - Specify the name of the Connect license secret - Verify that Scan Service is disabled - Set up PostgreSQL users and permissions - Set up PostgreSQL TLS - Specify the Connect Web URL - Optional: Set Coverity metrics keys - Optional: Prepare `cimweb` keys - Optional: Specify the Connect Web application administator   password secret - Optional: If you are deploying Connect Web application high   availability (HA) (multiple web application replicas), set the   `cim.cimweb.replicas` Helm key, set the   `commitrcp2` Helm keys, and perform any other   tasks as needed for your HA deployment. - Optional: If you are deploying PostgreSQL database read   replicas, create the replica databases and configure the Helm   keys as needed. | Preparing Helm keys to deploy Coverity   - imageRegistry keys - Enable Connect - Specify the name of the Connect license secret - Disabling the scan-services Helm subchart for a Connect-only deployment - Create PostgreSQL database access credentials - Select the PostgreSQL sslmode and find the PostgreSQL root certificate for TLS - Specify the Coverity Connect Web URL - Enabling Coverity metrics through Helm overrides - Preparing cim.cimweb Helm keys - Set the cim.cimweb.adminPasswordSecret Helm key - Connect Web application high availability - Optional: Using PostgreSQL read replicas and Pgpool to balance database loads |
| 12 | - Configure pod and container security. | - Configuring pod and container security |
| 13 | Build a full analysis kit and configure the Helm chart to automatically upload the kit to Connect during deployment. | - Building a full analysis kit and automatically uploading the kit to Connect during deployment |
| 14 | If you are deploying AI-Assisted Triage Plug-in, configure Helm keys and perform the deployment.  Important: AI-Assisted Triage Plug-in is a Beta release feature. | - Deploying the AI-Assisted Triage Plug-in |
| 15 | Run a `helm install` to deploy Coverity Connect in the Kubernetes cluster. | - Installing chart releases for your deployment |
| 16 | Complete any post-install tasks, including the following:   - Obtain the Coverity Connect URL and login to the Coverity   Connect UI. - Configure SAML using the Coverity Connect UI. - Configure other tools or protocols as needed. | - Post installation or upgrade tasks - Accessing the Connect UI - Configuring SAML |
| 17 | Verify the Coverity cloud deployment. | - Verifying the Coverity cloud deployment |
| 18 | Optional: If you deployed or need to deploy multiple replicas of the Connect web application for web app HA, manage the HA deployment. | - Connect Web application high availability |
| 19 | Create a full Coverity Analysis client image which enables end users can download and install on their client system to perform a local analysis. | - Building a full analysis kit and automatically uploading the kit to Connect during deployment |
| 20 | End users (programmers): For local analysis: Install the full Coverity Analysis client from the Connect UI Downloads page. | - See the section, Installing Coverity Analysis for local   analysis in the Coverity 2026.6.0 Installation and Upgrade Guide. |
| 21 | End users (programmers) can prepare for and perform analyses. | - What is next? preparing and performing analyses |
