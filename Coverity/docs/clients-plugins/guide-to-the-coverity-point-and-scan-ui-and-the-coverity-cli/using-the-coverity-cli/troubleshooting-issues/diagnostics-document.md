# Diagnostics document

The Coverity CLI diagnostics document is a JSON document that can be useful for getting a more detailed understanding of the steps that Coverity
took to capture and analyze the project. It also records the configuration that was used for each stage of the scan.

The JSON document contains five top-level keys: `"type"`, `"version"`, `"general"`,
`"capture"`, and `"analysis"`.

- The `"type"` key indicates the type of information contained in the document. It is always set to `"Coverity CLI Diagnostics Data"`.
- The `"version"` key identifies the version of the schema for the information.
- The `"general"` key contains the Coverity version, which applies to both the capture and the analysis
  of the project in question.
- The `"capture"` and `"analysis"` keys contain diagnostics information for the capture and analysis stages of the scan.
  Each of these includes a `"command-info"` key that is an array of objects.
  Each entry in the array corresponds to a command that was executed in the course of the corresponding scan stage, either code capture or code analysis.

Note:
Much of information shown in the diagnostics document is self-explanatory. Some keys deserve special explanation.
See Contents of a `command-info` entry for a
description of the fields used by entries in the `"command-info"` arrays.

## Generating and managing diagnostic JSON files

The diagnostic JSON document is uploaded to Coverity Connect during the commit step.
The file can then be downloaded for a particular snapshot from Coverity Connect
by sending an HTTP GET request to

```
<server-url>/api/v2/snapshots/{id}/outputFile/cli-diagnostics.json
```

For example, if the Coverity Connect hostname is acme.connect.com and the snapshot ID is `1234`,
then the complete URL would be as follows:

```
https://acme.connect.com/api/v2/snapshots/1234/outputFile/cli-diagnostics.json
```

... and a complete command line to obtain the JSON document might appear like this:

```
curl -s -X 'GET' 'https://acme.connect.com/api/v2/snapshots/1234/outputFile/cli-diagnostics.json”.?locale=en_us' \
                -H 'accept: application/json' -H 'Authorization: Basic YWRtaW46QzB2ZXIxdHkh' \
                |jq -r '.contents' |base64 -d |zlib-flate -uncompress
```

## Contents of a `command-info` entry

Each `"command-info"` entry contains the keys shown in the following table.

In each entry, the keys appear in the following order (not every field necessarily appears in every
`command-info` array):

1. `command-line`
2. `cwd`
3. `env`
4. `exit-code`
5. `stdout-tail`
6. `stderr-tail`
7. `start-time`
8. `end-time`
9. `duration`
10. `meta`

| Key | Type | Description |
| --- | --- | --- |
| `command-line` | string | The command line that was used to execute the command this entry describes. |
| `cwd` | string | The current working directory for this command. |
| `duration` | integer | The length of time for which this command ran, in nanoseconds. |
| `end-time` | string | The time when this command completed. This is expressed in [RFC3339 format](https://www.rfc-editor.org/rfc/rfc3339) with the seconds shown as a decimal to nanosecond precision. |
| `env` | object | An object in which each entry corresponds to the name of an environment variable and its value. Note: For security reasons, only the PATH environment variable and pertinent Coverity Analysis environment variables are saved in the `env` object. |
| `exit-code` | integer | The code which this command issued upon exiting. |
| `meta` | object | An object that contains metadata about the command that was executed. This object is populated only for invocations of `cov-build`. It contains a single entry named `"build-metrics"`, which contains metrics data generated by `cov-build`. |
| `start-time` |  | The time when this command was invoked. This is expressed in [RFC3339 format](https://www.rfc-editor.org/rfc/rfc3339) with the seconds shown as a decimal to nanosecond precision. |
| `stderr-tail` | array of strings | Contains the last lines, up to 10, of output written to the stdout file. |
| `stdout-tail` | array of strings | Contains the last lines, up to 10, of output written to the stderr file. |
